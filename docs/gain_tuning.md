# 게인 튜닝과 오버슈트 줄이기 (공부 노트)

작성: 2026-11-02 · Gazebo Harmonic, ROS 2 Jazzy, gz_ros2_control 1.2.19, DART (Bullet 충돌 검출), 물리 4 ms

WAM-V 위 UR5 를 Gazebo 에서 위치 제어할 때 **응답 속도(게인)를 어떻게 정했는지**, **오버슈트가 왜 생기고 어떻게 줄이는지**를
측정값과 함께 정리한다. 설정과 구조는 [`ros2_control.md`](ros2_control.md).

> **측정 조건 주의**: 1~3 장의 숫자는 인터페이스 단계 **전** (물리 250 Hz, forward_command_controller, 명령 보간 없음) 에 쟀다.
> 지금은 물리 240 Hz (τ = 1/(0.15 × 240) = 27.8 ms) 이고, `drive_test.py` 는 `/joint_command` 를 거쳐 **33 ms 보간이 들어간 응답**을 잰다
> (시험 A 정착 0.121 s, 시험 C 지연 46~48 ms, [`interface.md`](interface.md) 5 장). 게인만 따로 보려면 보간 전 숫자와 비교한다.

## 1. 제어 루프 모델

### 1.1 gz_ros2_control 의 위치 명령

`gz_ros2_control` 은 position 명령을 **속도 명령**으로 바꿔 물리 엔진에 준다 (250 Hz 마다):

```text
v_cmd = Kp × (q_target − q) × f        Kp = position_proportional_gain, f = update_rate = 250 Hz
```

DART 는 이 속도를 관절 effort 한계 (UR5: 어깨·팔꿈치 150 Nm, 손목 28 Nm) 안에서 지키려고 한다.
속도가 오차에 비례하므로 **1 차 시스템**이다:

```text
dq/dt = (Kp·f) · (q_target − q)    →    q(t) = q_target · (1 − e^(−t/τ)),   τ = 1 / (Kp · f)
```

| 지표 | 1 차 시스템 공식 |
|---|---|
| 50 % 도달 | 0.69 τ |
| 90 % 도달 | 2.3 τ |
| 2 % 정착 | 3.9 τ |
| 천천히 변하는 명령 (사인파) 의 지연 | 약 τ (위상 지연 atan(ωτ) / ω, ωτ ≪ 1 이면 τ) |
| 오버슈트 | **0** (1 차 시스템은 넘치지 않는다) |

### 1.2 공식 vs 측정

| Kp | τ = 1/(Kp·250) | 시험 C 지연 (측정) | 3.9 τ | 시험 A 정착 (측정) |
|---|---|---|---|---|
| 0.1 | 40 ms | 38 ms | 156 ms | 0.15 ~ 0.16 s |
| 0.15 | 26.7 ms | 24 ~ 30 ms | 104 ms | 0.10 ~ 0.11 s |
| 0.2 | 20 ms | 22 ms | 78 ms | (안 잼) |

**모델이 측정과 잘 맞는다** → 작은 명령에서는 Gazebo 관절이 거의 이상적인 1 차 시스템처럼 움직인다.

0.05 rad 계단 (모든 관절 동시, Kp 0.15) 을 보면: t = 32 ms 에서 손목 관절 0.034 / 0.05 = 68 % (공식 1 − e^(−32/26.7) = 70 %).
어깨 관절은 조금 느리다 (32 ms 에 48 %) — 무거운 링크를 가속하는 데 시간이 걸린다 (모델에 없는 관성).

### 1.3 이산 시간 안정 조건

한 제어 주기 (dt = 1/f) 동안 줄어드는 오차 비율 = Kp·f·dt = **Kp**.

| Kp | 의미 |
|---|---|
| 0 < Kp < 1 | 매 주기 오차의 Kp 만큼 줄어듦, 넘치지 않음 |
| Kp = 1 | 한 주기에 목표 도달 (deadbeat, 이론상) |
| 1 < Kp < 2 | 매 주기 목표를 넘었다 돌아옴 (진동하며 수렴) |
| Kp ≥ 2 | 발산 |

실제로는 속도 한계·관성 때문에 Kp 를 크게 해도 그만큼 빨라지지 않는다 (다음 장).

## 2. 게인 결정 (Kp = 0.15)

기준은 Isaac Sim drive 튜닝 시험 (`data_collection_ur5_gripper/docs/drive_tuning.md` 8 장) 과 같다.

- **시험 A**: 관절 하나씩 0.05 rad 계단. 50 Hz 텔레옵 한 스텝 최대 변화 ≈ 0.063 rad 라서 이 크기로 판정
- **시험 C**: 50 Hz 계단 명령으로 만든 0.5 Hz 사인파 (진폭 0.3 rad). 지연 = 명령을 0 ~ 100 ms 밀어 가며 응답과의 오차 제곱합이 최소인 이동량

| Kp | C 지연 | C RMS | A 오버슈트 |
|---|---|---|---|
| 0.1 (기본) | 38 ms | 1.55° | 0 % |
| **0.15 (채택)** | **24 ~ 30 ms** | **0.97 ~ 1.12°** | **0 %** |
| 0.2 | 22 ms | 0.82 ~ 0.88° | |
| *Isaac Sim (PD)* | *19 ~ 34 ms* | *0.7 ~ 1.3°* | *최대 1.2 %* |
| *기준* | *< 40 ms* | | *< 2 %* |

Isaac Sim 결과 범위의 가운데 + 0.2 보다 덜 공격적 → 0.15.
(같은 Kp 에서도 실행마다 지연이 2 ~ 6 ms 다르다: 측정이 2 ms 간격이고 명령 시각과 제어 주기의 위상이 매번 달라서)

## 3. 오버슈트는 왜 생기나: 큰 계단 (0.2 rad)

### 3.1 측정

**`shoulder_lift_joint` 하나만 +0.2 rad** (`--tests step --step 0.2 --joint shoulder_lift_joint`):

| t [s] | 0.012 | 0.032 | 0.048 | 0.064 | 0.080 | 0.100 | 0.120 | 0.160 | 0.200 | 0.300 | 0.500 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| q − home [rad] | 0.004 | 0.036 | 0.083 | 0.133 | 0.184 | 0.247 | 0.309 | 0.435 | 0.561 | 0.392 | 0.200 |

- t ≈ 0.04 s 부터 **16 ms 마다 0.050 rad = 3.14 rad/s = 관절 속도 한계 (URDF π rad/s, UR5 180°/s)** 로 움직임
- t ≈ 0.085 s 에 목표 (0.2) 를 지나고도 **t ≈ 0.2 s 까지 같은 속도**로 계속 가서 최대 약 0.58 rad (오버슈트 약 190 %), 0.5 s 에 목표로 돌아옴
- **Kp 0.1 과 0.15 에서 이 궤적이 소수점 넷째 자리까지 같다** (0.12 s: 0.3093 vs 0.3094, 0.2 s: 0.5607 vs 0.5607)
  → 속도 한계에 걸린 동안은 **게인이 아무 영향이 없다**

**모든 관절 동시 +0.2 rad** (Kp 0.15): shoulder_lift 84 %, elbow 31 %, wrist_2 25 %, 나머지 0 %.
같은 명령을 다른 실행 (Kp 0.1) 에서 했을 때 shoulder_lift 155 %, wrist_2 55 % → **실행마다 크게 다름**.

**모든 관절 동시 +0.05 rad**: 6 관절 모두 오버슈트 0 %.

### 3.2 속도 포화 경계

명령 속도 Kp·f·e 가 속도 한계 v_max 를 넘으면 포화된다:

```text
e_sat = v_max / (Kp · f) = π / (0.15 × 250) = 0.084 rad
```

- 0.05 rad 계단 < 0.084 → 포화 없음 → 1 차 시스템 그대로 (오버슈트 0)
- 0.2 rad 계단 > 0.084 → 포화 → 모델에서 벗어남
- Kp 를 키우면 e_sat 이 작아져 **더 작은 계단에서도 포화**된다 (Kp 0.2: 0.063 rad = 텔레옵 한 스텝 최대 변화와 같음)

### 3.3 원인 (확인한 것과 추정)

| | 내용 | 상태 |
|---|---|---|
| 속도 포화 | 큰 오차에서 명령 속도가 π rad/s 를 넘고, 관절이 한계 속도로 움직인다 | **측정으로 확인** |
| 중력 방향 | shoulder_lift +0.2 rad 는 중력이 미는 방향 (홈 자세에서 위팔이 수직, 앞으로 기울어짐) | 확인 |
| 감속 부족 | 목표를 지나면 v_cmd 는 반대 부호가 되는데, 관절은 약 0.1 s 동안 **감속 없이** 한계 속도를 유지했다 | 측정으로 확인. **이유는 미확인** |
| 토크 포화? | 멈추려면 감속 토크가 필요하고, 쓸 수 있는 토크 = 150 Nm − 중력 토크. Isaac Sim 0.2 rad 계단 오버슈트 13.6 % 의 원인으로 기록된 것 | 추정. 대략 계산하면 (관성 약 2 kg·m², 중력 약 20 Nm) 50 ms 안에 멈출 수 있어야 해서 **이것만으로는 0.1 s 동안 감속이 없는 것을 설명하기 어렵다** |
| DART 속도 명령 / 속도 한계 처리 | 속도 명령 (servo) 과 속도 한계 제약이 동시에 걸릴 때의 처리 방식 | **추정, 미확인** |
| 관절 결합 | 모든 관절을 동시에 움직이면 다른 관절의 반작용 토크가 손목 effort 한계 (28 Nm) 를 넘는다 → wrist_2 오버슈트는 동시 계단에서만 생김 | 추정 (혼자 움직일 때 0 % 는 확인) |

### 3.4 더 파 보기 (연습 문제)

1. **방향 바꾸기**: `--step -0.2 --joint shoulder_lift_joint` (중력 반대 방향). 오버슈트가 줄면 중력·토크 쪽 설명이 맞다
2. **토크 기록**: `ur5_rh_p12.ros2_control.xacro` 의 팔 관절에 `<state_interface name="effort"/>` 를 추가하면 `/joint_states` 에 effort 가 나온다.
   목표를 지나는 순간 effort 가 150 Nm 에 붙어 있으면 토크 포화
3. **속도 한계 바꾸기**: URDF 관절 velocity limit 을 잠깐 2π 로 올려 보기 (`ur_description` 의 `joint_limits.yaml` 을 복사해 `joint_limits_parameters_file` 로 넘김).
   포화 경계 e_sat 이 두 배가 되는지, 감속 없는 구간이 사라지는지
4. **게인과 무관함 확인**: Kp 0.05 / 0.3 에서 같은 0.2 rad 계단 — 포화 구간 궤적이 같은지

## 4. 오버슈트 줄이는 방법

### 4.1 명령을 다듬기 (입력 쪽) ← 실제로 쓰는 방법

포화를 만드는 것은 **큰 오차**다. 명령이 한 번에 크게 뛰지 않게 하면 포화가 안 생긴다.

| 방법 | 내용 | 이 프로젝트 |
|---|---|---|
| **선형 보간** | 새 명령까지 일정 시간 (33 ms) 동안 직선으로 이동 | Isaac Sim `command_interp_time` 0.033 s, 다음 단계 변환 노드에서 같게 구현 |
| 속도 제한기 (rate limiter) | 한 주기당 명령 변화량을 v_lim·dt 로 자름 | 필요하면 변환 노드에 추가 |
| 궤적 생성 | 속도·가속도 (·저크) 한계를 지키는 궤적으로 명령 (`joint_trajectory_controller`, Ruckig 등) | 정책은 매 칸 절대각을 주므로 지금은 보간으로 충분 |

조건: 보간 중 추종 오차 ≈ v·τ (속도 v 로 움직이는 명령을 시상수 τ 로 따라감).
v = π rad/s 에서 e ≈ π × 0.0267 = 0.084 rad = e_sat → **명령 속도가 관절 속도 한계 이하면 포화가 안 생긴다.**
정책·텔레옵 명령은 이보다 훨씬 느리다 (시험 C 사인파 최대 속도 0.3 × 2π × 0.5 = 0.94 rad/s → 오차 약 0.025 rad).

### 4.2 게인 낮추기

Kp 를 낮추면 e_sat 이 커져 포화가 덜 생기지만 지연이 늘어난다 (τ = 1/(Kp·f)). 포화된 뒤의 궤적에는 효과가 없다 (3.1).
→ 지연을 Isaac Sim 에 맞추는 것이 목적이라 Kp 로 오버슈트를 잡지 않는다.

### 4.3 PD (effort 제어) 로 바꿀 때

Isaac Sim 처럼 토크 = K·(q_target − q) − D·q̇ 로 바꾸면 (effort command interface + PID 컨트롤러) 2 차 시스템이 된다:

```text
I·q̈ = K·e − D·q̇          ω_n = √(K/I),   ζ = D / (2·√(K·I))
오버슈트 = exp(−π ζ / √(1 − ζ²))   (ζ < 1),   ζ ≥ 1 이면 0
```

| ζ | 오버슈트 |
|---|---|
| 0.5 | 16 % |
| 0.7 | 4.6 % |
| 1.0 (임계 감쇠) | 0 % |

Isaac Sim 값 (`data_collection_ur5_gripper/isaacsim/config/drive_gains.yaml`): K = I·ω², D = 2·I·ω (ζ = 1), ω ≥ 100 rad/s.
예: shoulder_lift K 85488 Nm/rad, D 1399.75 Nm·s/rad.

**주의 — 그대로 옮기면 안 되는 이유**: PhysX drive 는 implicit (다음 상태를 풀어서 계산) 이라 큰 K 에서도 안정하다.
Gazebo 에서 250 Hz 로 토크를 계산해 넣는 explicit PD 는 대략 ω_n·dt 가 커지면 불안정해진다
(ω_n = 122 rad/s, dt = 4 ms → ω_n·dt ≈ 0.5, 감쇠항 2ζω_n·dt ≈ 1 로 경계에 가까움). 다시 튜닝이 필요하다.

그 밖의 도구:

| 방법 | 효과 |
|---|---|
| 중력 보상 feedforward | 토크에 중력 토크를 미리 더함 → 처짐 0, 위·아래 방향 비대칭 감소 (Isaac Sim `gravity_ff` 옵션) |
| 속도 feedforward | 명령 속도를 미리 더함 → 지연 감소, 피드백 게인을 낮출 수 있음 |
| 적분항 (I) + anti-windup | 정상상태 오차 제거. 포화 중 적분이 쌓이면 큰 오버슈트 → 포화 시 적분 멈춤 |
| armature (회전자 관성) | 관절에 관성을 더해 solver 안정 (Isaac Sim 그리퍼 0.01) |

### 4.4 물리 한계 바꾸기

effort·속도 한계를 올리면 포화가 줄지만 **실물 UR5 (150/28 Nm, 180°/s) 와 달라진다**. sim2sim/sim2real 목적에서는 쓰지 않는다.

## 5. 요약

| 상황 | 동작 | 오버슈트 |
|---|---|---|
| 작은 명령 (오차 < 0.084 rad) | 1 차 시스템, τ = 1/(Kp·250) = 26.7 ms | 0 |
| 큰 계단 (오차 > 0.084 rad) | 속도 한계 π rad/s 로 포화, 게인 무관 | 25 ~ 190 % (관절·방향·실행마다 다름) |
| 정책·텔레옵 (60 Hz 명령 + 33 ms 보간) | 작은 명령 영역 | 0 (시험 A·C) |

- 게인 (Kp 0.15) 은 **지연을 Isaac Sim 에 맞추는 용도**
- 오버슈트는 **명령을 다듬어서 (보간·속도 제한) 포화를 피하는 것**으로 막는다
- 큰 계단에서 "목표를 지나도 감속 없이 0.1 s" 의 정확한 이유는 아직 모른다 (3.3, 3.4 연습 문제)

## 6. 용어

| 용어 | 뜻 |
|---|---|
| 오버슈트 | 목표를 넘어간 최대량 / 명령 크기 × 100 % |
| 정착 시간 (2 %) | 이후 계속 목표의 ±2 % 안에 머무는 첫 시각 |
| 시상수 τ | 1 차 시스템이 남은 오차의 63 % 를 줄이는 시간 |
| 포화 | 명령이 한계 (속도·토크) 를 넘어 잘리는 상태. 이때는 선형 모델이 맞지 않는다 |
| implicit / explicit | 다음 스텝 상태를 방정식으로 풀어 구함 / 지금 상태로 바로 계산. implicit 이 큰 게인에서 안정 |
| ζ (감쇠비) | 2 차 시스템의 감쇠 정도. 1 이면 임계 감쇠 (넘치지 않는 가장 빠른 응답) |
